# 城堡定时结算配置（NAS / 容器部署）

## 背景

城堡的「每日结算」（`settleCastle`：捣蛋萌可捣乱、萌可成长刷新、连续打卡统计）原本只在**有人打开城堡页 / 调用 `getCastleState` 时懒触发**。
在 NAS 长期运行、但孩子未必每天打开页面的场景里，这没问题；但如果你想让结算**稳定地每天发生**（例如让「昨天没打卡→今天被捣蛋萌可占领」这类反馈及时生效），就需要一个定时触发器。

项目已内置接口：

```
POST /api/cron/settle
```

它会：
1. 用 `CRON_SECRET` 鉴权（无密钥 → 401）；
2. 清理过期会话（与 cookie 7 天 maxAge 对齐）；
3. 遍历所有孩子账号，逐个触发一次 `getCastleState`（进而执行 `settleCastle`）。

---

## 一、先设置 CRON_SECRET

接口必须带密钥，否则永远 401。在部署目录的 `.env` 里加一行（值与 `.env.example` 对齐）：

```bash
# 生成一个足够随机的值
openssl rand -hex 32
# 写入 .env
CRON_SECRET=<上面生成的值>
```

`docker-compose.yml` 已配置 `- CRON_SECRET=${CRON_SECRET}`，compose 会自动用同目录 `.env` 注入容器。
改完后重建容器让环境变量生效：

```bash
docker compose up -d --force-recreate chengcheng
```

---

## 二、触发方式（任选其一）

### 方式 A：飞牛 FnOS「计划任务」（推荐，最省心）

FnOS 自带计划任务（或「盒子」里的定时脚本）。新建一个每日任务（例如每天 03:00，避开孩子使用高峰），内容：

```bash
CRON_SECRET=<你的密钥> /vol1/1000/Docker/chengcheng-workbench/scripts/settle-cron.sh >> /vol1/1000/Docker/chengcheng-workbench/logs/settle.log 2>&1
```

> 脚本默认打 `http://localhost:3000/api/cron/settle`。若你想从 NAS 宿主机调容器，确认 `localhost:3000` 可达（容器 `ports: 3000:3000` 已映射）；
> 若改过端口或想从容器外网访问，用 `SETTLE_URL=http://<容器IP>:3000/api/cron/settle` 覆盖。

### 方式 B：容器内部 cron（把脚本放进容器）

在 `Dockerfile` 里加一条 `crontab`（或在 `docker-compose` 用 `command` 起一个 cron 进程），每日 03:00 执行容器内脚本：

```cron
0 3 * * * CRON_SECRET=<你的密钥> /app/scripts/settle-cron.sh >> /app/logs/settle.log 2>&1
```

> 注意：默认镜像没有 cron 守护进程，`Dockerfile`/compose 需额外安装并启动（如 `apt-get install -y cron && cron`）。方式 A 通常更简单。

### 方式 C：外部调度器

任意能定时的地方（路由器、另一台机器、Vercel Cron、云函数）按时 `POST` 一次即可：

```bash
curl -X POST -H "Authorization: <你的密钥>" "https://你的域名/api/cron/settle?secret=<你的密钥>"
```

---

## 三、验证

手动跑一次，看到 `OK settle: HTTP 200` 即成功：

```bash
CRON_SECRET=<你的密钥> ./scripts/settle-cron.sh
```

失败排查：
- `HTTP 401` → `CRON_SECRET` 没注入容器（检查 `.env` 与 `docker compose up -d --force-recreate`）。
- `HTTP 000` → 容器没起来 / 端口不对，确认 `curl http://localhost:3000/` 能通。
- 脚本退出码 `2` → 没传 `CRON_SECRET` 环境变量。

---

## 四、频率建议

- **每天 1 次**已足够（结算窗口是「上次结算日+1 ～ 昨天」，多次调用幂等，不会重复惩罚）。
- 想更及时可改每小时 1 次，开销极小（只是遍历孩子跑几个 UPDATE）。
- 时区：容器已设 `TZ=Asia/Shanghai`，结算按北京时间算「今天」，无需额外处理。
