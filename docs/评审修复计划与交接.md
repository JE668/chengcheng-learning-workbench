## 3. 逐项详情（问题 / 改法）

### 3.1 CI 与构建优化
- **问题**：`build.yml` 构建 `linux/amd64,linux/arm64`，arm64 靠 QEMU 模拟，是单次 20+ 分钟构建的大头；且 `ci.yml` 自身监听 `push: main`，而 `build.yml` 的 precheck 又 `uses:` 复用了同一个 workflow → 每次 push 完整跑两遍 CI。
- **改法**：platforms 改为 `linux/amd64`（注释说明换 ARM 设备时怎么改回）；`ci.yml` 去掉 `push` 触发，只保留 `pull_request` + `workflow_call`。
- **注意**：若你在 GitHub 上给 main 配了 required status check「CI / check」，去掉 push 触发后该检查可能长期 pending。你是单人直推 main，不受影响；将来若加分支保护需留意。

### 3.2 时区与 CRON_SECRET
- **问题**：文档推荐的 `docker-compose.ghcr.yml` **缺 TZ 与 CRON_SECRET**。缺 TZ → 容器跑 UTC，`dateStr()` 与 `DATE(created_at,'localtime')` 让「今天」偏移 8 小时（打卡/连击/结算/每日一练全错）；缺 CRON_SECRET → `/api/cron/*` 恒 401，每日结算与备份静默永不执行。
- **改法**：两个 compose 都补 `TZ=Asia/Shanghai` + `CRON_SECRET`；`Dockerfile` 的 runner 层安装 `tzdata` 并 `ENV TZ=Asia/Shanghai` 兜底（debian slim 默认不含 tzdata，缺了 TZ 会静默退回 UTC）。
- **⚠️ 需要在 NAS 上补一步**：在 `docker-compose.ghcr.yml` 同级建 `.env`：
  ```
  CRON_SECRET=<用 openssl rand -hex 32 生成>
  ```

### 3.3 依赖漏洞
- **问题**：Security Scan 自 2026-09-29 起连续 4 天失败，根因是 npm audit 门禁被新 advisory 打爆；同样的步骤在 `ci.yml` 里也有一份，且 `build.yml` 依赖它 → **下一次 push 会因 precheck 失败而不出镜像**。
- **改法**：`package.json` 的 `pnpm.overrides` 增加
  `fast-uri: ^3.1.8`、`undici: ^7.29.1`、`brace-expansion@1/2/5: ^1.1.20 / ^2.1.6 / ^5.0.11`
  （按 major 分别 pin，避免把 eslint 依赖的 1.x 强提到 5.x）。
- **验证**：`pnpm audit` 判定「可操作 high/critical = 0」，剩余仅 next 的已知豁免。
- **仍未解决**：`next` 已有 2 个 **critical** advisory，14.x 无修复版本 → 需要排期升级 Next 15 + React 19。

### 3.4 VAPID 密钥
- **问题**：私钥硬编码在 `src/lib/push-notifications.ts` 与 `.env.example`；**公钥**还硬编码在两个客户端组件里。仓库是 public → 等同于公开泄露（可被伪造推送）。
- **改法**：源码中彻底移除两把密钥；改为只读环境变量（`VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY`，兼容旧的 `NEXT_PUBLIC_*`）；公钥改由 `GET /api/push/subscribe` 下发，客户端不再硬编码；未配置时 `isPushConfigured=false`，`sendPushNotification` 直接短路、`POST` 返回 503，**不会让模块 import 失败**。
- **⚠️ 你必须在 NAS 上做的事（重要）**：
  1. 旧密钥对已泄露，**必须作废**。生成新的：`npx web-push generate-vapid-keys`
  2. 在 NAS compose 同级 `.env` 写入 `VAPID_PUBLIC_KEY=...` 与 `VAPID_PRIVATE_KEY=...`（两个 compose 已透传这两个变量）。
  3. 未配置也能正常跑，只是推送功能关闭（浏览器端会提示「Web Push 未配置，跳过订阅」）。

### 3.5 Service Worker
- **问题**：`PRECACHE_URLS` 含 `/offline`，但仓库只有 `public/offline.html`、没有 `/offline` 路由 → 404 → `cache.addAll` 整体 reject → `install` 抛错 → **SW 永远装不上**（离线与 Web Push 全废）。另外：缓存了按孩子隔离的 `/api/*` 响应、`CLEAR_CACHES` 消息没人处理（登出不清缓存）、`cache.put` 未纳入 `waitUntil`。
- **改法**：`/offline` → `/offline.html`（两处）；install 改为逐条 `add` + `Promise.allSettled` 容错；`/api/*` 交给网络、完全不走 SW 缓存；实现 `CLEAR_CACHES`；缓存写入纳入 `event.waitUntil`；`CACHE_VERSION` 提到 `ccwb-v4` 以清掉旧缓存。
- **验证方式**：部署后 Chrome DevTools → Application → Service Workers，应看到 activated；断网刷新应显示离线页而不是登录页。**这一条无法在本地验证（无 Docker、无浏览器），请在真机确认。**

### 3.6 tts-edge Buffer 越界
- **问题**：`const body = buffer.buffer as ArrayBuffer` 丢弃 `byteOffset/byteLength`。`Buffer.concat` 小数据量时从共享内存池分配，`.buffer` 是整个 64KB 池 → 发出的不是这段音频（损坏）且**泄露进程内相邻内存**，`Content-Length` 也不符。
- **改法**：`new Uint8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength)`（零拷贝视图，尊重区间）。
- **验证**：本地复现过 `Buffer.concat(5500B)` → `byteOffset=5504, ArrayBuffer=65536`。

### 3.7～3.10 逻辑修复
- **study 页**：`loadRecommend()` 已解析 `childId` 却查询 `getModuleProgressAll(0)` / `getTextbookProgress(0)` → `child_id=0` 永远无数据 → 「继续学习」按钮与「该复习单元」标签**永久不显示**。改为传 `childId`。
- **auth**：`const SECURE_COOKIE = process.env.SECURE_COOKIE === 'true'` 是 boolean，导致 `if (SECURE_COOKIE !== undefined)` 恒真 → 反代 `x-forwarded-proto` 判断是**死代码**，HTTPS 反代下 cookie 不带 `Secure`。改为保留原始字符串做三态判断。
- **auth**：`getCurrentUser` 只按 token 查、不校验会话年龄（清理只在登录/cron 发生）→ 被盗 token 在 cookie 过期后仍长期有效。加 `AND s.created_at > datetime('now', '-' || ? || ' days')`。
- **sm2**：`cappedInterval` 算完从未使用，365 天上限失效 → 改用 `cappedInterval`；`toISOString().split('T')[0]` 取 UTC 日期 → 改 `formatDate()`（本地日，东八区早上 8 点前不再排早一天）。
- **backup**：`process.env.TURSO_URL || ''` 与 `db-core.ts` 的 `|| 'file:local.db'` 不一致 → 非 Docker 环境 `DB_FILE=null`，备份永不出库。已对齐。

### 3.11 schema 初始化与迁移竞态
- **问题**：根布局是 `force-dynamic`，**每个请求**都 `await ensureSchema()` → 2 个 PRAGMA + guard SELECT + 11 张表的**写事务** batch + 迁移检查，并发时争写锁；冷启动并发还可能同时通过 `isNewDb` 守卫而撞主键。
- **改法**：把「一个进程只跑一次」的记忆化放在**调用点**（`src/app/layout.tsx` 的 `ensureSchemaOncePerProcess`），**不改变 `ensureSchema()` 自身语义**——因为 `migrations.test.ts` 依赖它能被反复调用（曾试过在函数内记忆化，导致该测试失败，已回退）；`runMigrations` 的版本写入改为 `INSERT OR IGNORE`。

### 3.12 类型检查盲区
- **问题**：`tsconfig.json` 排除了 `src/hooks/**`、`src/lib/tts/**`、`src/lib/stores/index.ts`、`src/lib/index.ts`、`src/components/atomic/**`，加上 `next.config.mjs` 的 `typescript.ignoreBuildErrors`，使 `src/hooks/useUtils.ts` 里「非 async 函数里用 await」（TS1308）等多处错误长期存在。
- **改法**：`exclude` 只留 `node_modules`，然后修复暴露出的 **8 个真实类型错误**：`useUtils` 补 `async`、`useAsync` 显式无参调用、`useTTS`×4（`setPlaying` 的第二参允许 `null`，与实现里的 `item ?? null` 一致）、`src/lib/index.ts`×2（`addDaysToDate` 与 `Subject` 被多模块重复 star-export 产生 TS2308，改为显式命名导出消歧）。
- **附带发现**：`src/hooks/**` 全项目**零引用**（~960 行死代码）；`src/lib/index.ts` 这个 barrel 也**零引用**。两者都已在 git 里（可随时取回），是否删除由你决定。

### 3.13 移除 prebuild/postbuild 钩子
- **问题**：`scripts/stamp-sw.mjs` 依赖 `public/sw.js` 里的 `__SW_BUILD_ID__` 占位符，但该占位符早已不在文件里（脚本现在只会打印「已是打戳后内容，跳过」）→ prebuild 空转。更危险的是 `postbuild: git checkout -- public/sw.js`：**任何本地 `pnpm build` 都会把 `public/sw.js` 回滚成 git 版本，静默抹掉未提交的 SW 改动**。
- **改法**：删掉 `prebuild` 与 `postbuild` 两个钩子。今后**修改 SW 逻辑时必须手动提升 `CACHE_VERSION`**（当前 `ccwb-v4`）。

### 3.14 P0 批次：堵住「客户端可伪造奖励 / 可绕过限流 / 公开探测面」

**（a）游戏积分（`tasks/game-complete`）**：原来 `points = Math.max(0, Math.floor(Number(score) || 0))`，
score 由客户端给且无上限——孩子 POST score 为 1e9 就能凭空造出任意积分。
现改为：gameId 必须命中 `lib/moko.ts` 的 15 个已知游戏（杜绝用任意字符串刷记录），
分数钳制在 `[0, 500]`（500 取自各游戏自己的计分公式上限约 420，不会削减正常奖励），
超限时打 warn 日志留痕。**残留**：彻底杜绝需要把游戏判定搬到服务端，成本高，仍属待办。

**（b）算法关卡星级（`algorithm-progress`）——这一条做成了服务端权威**：
原实现 `ratio = correctCount / totalCount`，两者都来自客户端，报 `totalCount: 0`
就得到 `Infinity` → 直接 3 星。现在：
- topicId 必须在 `ALGORITHM_GENERATORS` 中，level 必须是 1–10 的整数；
- **分母改用服务端自己生成的题量** `genPracticeSet(topicId, lv).length`（恒为 10），
  客户端上报的 totalCount 不再参与星级计算 → 「报 1 题答对 1 题拿 3 星」失效；
- 答对数取 `min(客户端上报, 题量 − 错题数)`，正常提交不受影响（客户端保证
  correct + mistakes 条数 == 题量），但 `correctCount: 999` 会被压回；
- mistakes 逐项校验类型与长度，并按题量截断（同时消除一次请求写爆库的风险）。

**（c）模块星级（`module-progress`）**：新增 (subject, moduleKey) 必须存在于
`STUDY_MODULES` 的白名单校验，并显式拒绝 `Number('abc')` 得到的 NaN（原先会被写进库）。
**残留**：stars 仍由客户端上报，真正的服务端判定需要把答题判分搬到服务端。

**（d）限流（`lib/rate-limit.ts`）**：`getClientIp` 原来取 `X-Forwarded-For` 的**第一个**值，
而该值由请求方控制 → 每个请求换一个假 IP 即可绕过全部限流（登录爆破、TTS 滥用）。
现改取**最后一跳**（反代追加的才是真实客户端 IP）。两个内存 Map 也加了容量上限与淘汰，
避免用大量不同 key（伪造 IP / 用户名）撑爆内存。
**注意**：若部署前面没有反代，XFF 仍可被伪造，应在反代层用 `proxy_set_header` 覆盖。

**（e）`tts-debug`**：会主动对外探测并回传上游错误原文，属开发诊断工具。
现默认返回 404，仅在 `.env` 设 `ENABLE_TTS_DEBUG=true` 并重建容器后才启用。

**（f）`tts/health`**：原先公开无鉴权，且**每个请求**都 `execSync('python3 --version')`
阻塞事件循环 → 单进程 NAS 上的现成 DoS 面。现加 60 秒 TTL 缓存（探测退化为廉价操作）+ 每 IP 30 次/分钟限流。

**（g）推送 endpoint（`push/subscribe`）**：该值会存库并由 web-push 主动 POST。
原先不校验，任何登录用户（含孩子）都能把它指向家庭内网地址，把服务器变成内网探测器。
现要求 https + 带点域名，并显式排除 IP 字面量（IPv4 点分十进制 / 含冒号的 IPv6）
与 `.local`/`.internal` 后缀，足以切断 SSRF。另给 `push/test` 加了 3 次/分钟限流与未配置守卫。
